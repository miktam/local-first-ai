# exp_051: MLX against Ollama on the same text

**Registered 2026-10-24, before any measured call.** Andrei asked for it in this session ("register 51 and run it"), and that is the sign-off. Kit: `kit/` (`bench51.py`, `score51.py`, `run51.sh`, `build_natural.py`). Inputs are frozen by the hashes below.

## Why

exp_011 (9 June) published three findings:
- MLX shows no prefill cliff through 40K tokens on the Mac mini.
- Its prefill matches Ollama's within 3 %.
- It generates faster at short context.

On 2026-10-24 we found that exp_011's MLX script looked for `15k.txt` while the fixtures are named `pad_15k.txt`. So every MLX call used its fallback: "The quick brown fox jumps over the lazy dog." repeated and cut at four characters per target token. The two runtimes were therefore compared on different text at different lengths.

Checking the fixtures for this registration turned up a second problem: exp_007's "real" fixtures are not natural text either. Each one cycles the same 31 sentences.

This experiment re-runs the comparison three ways:
- on the fixtures Ollama was measured on;
- on exp_011's actual MLX input;
- on natural, non-repeating text.

Both runtimes run the same day, under the same protocol.

## Arms

All arms use the same model family: Gemma 4 26B-A4B (MoE, about 4B active parameters per token).

| Arm | Runtime and build | Text | Sizes |
|---|---|---|---|
| **O** | Ollama 0.40.2, `gemma4:26b` (GGUF Q4_K_M, digest `777b927e3b6b`, llama.cpp runner), production settings (`OLLAMA_FLASH_ATTENTION=0`, default fp16 KV cache), `num_ctx` 65536 | exp_007 fixtures `pad_<size>.txt` | 4k 8k 15k 20k 25k 30k 35k 40k |
| **X** | mlx 0.32.4 and mlx-lm 0.32.2 (latest releases, installed 2026-10-24), `mlx-community/gemma-4-26B-A4B-it-OptiQ-4bit` (snapshot `dbfd2a77`, exp_011's build: mixed precision, 5.0 bits per weight), mlx-lm's default unquantised KV cache | same fixtures | same 8 |
| **F** | as X | exp_011's fallback text, generated by its own code (verbatim in `bench51.fallback`) | same 8 |
| **ON** | as O | natural text: `natural/nat_<size>.txt` | 4k 15k 25k 35k |
| **XN** | as X | the same natural text | same 4 |
| **O_drift** | as O | `pad_15k.txt` | 15k |

**The natural text.** It is exp_043's, exp_044's and exp_049's published synthetic test enquiries, in file order and joined by blank lines (`kit/build_natural.py`). Each file is cut at the last whole enquiry that keeps the raw text at or under the target size in Gemma 4 tokens. No enquiry repeats. The enquiries are in seven languages.

## Protocol (every call, every arm)

- **The message.** The user message is `Request <nonce>.\n\n` + text + `\n\nWrite a one-sentence summary of the text above.`
  - The nonce is 8 new hex characters per call, so neither runtime can reuse a prompt cache.
  - Each runtime applies its own chat template, with thinking off (Ollama `think: false`; MLX `enable_thinking=False`).
- **Decoding.** Greedy (temperature 0), at most 128 new tokens.
- **Repetitions.** 3 per size, with 20 s idle before each size. Every size's value is the **median of its clean repetitions**. A size needs at least 2 clean repetitions, or the hypotheses that use it are "not decided".
- **Order.** O, ON, X, XN, F, then O_drift. Then the models that were resident before the run (`gemma4:26b`, `gemma4:e4b`) are loaded again.
- **Memory.**
  - During O and ON, only `gemma4:26b` is loaded in Ollama.
  - During the MLX arms, no Ollama model is loaded: any found loaded is stopped before the call, and the MLX process holds the only model.
- **Outside requests.** Hermes and the CasaSol bot share this Ollama.
  - After every call, the Ollama log is read from the call's start.
  - A POST line other than the call's own (none in the MLX arms, one in the Ollama arms) marks the call contaminated, and the call is repeated, at most twice.
  - Every attempt is kept in `calls.jsonl`.
- **What is measured.**
  - **Prefill ms per token.** Ollama: `prompt_eval_duration / prompt_eval_count`. MLX: `1000 / prompt_tps` from `stream_generate`'s last response, which runs to the first generated token.
  - **Generation tokens per second.** Ollama: `eval_count / eval_duration`. MLX: `generation_tps`.
  - Also recorded per call: prompt tokens, generated tokens, finish reason, the first 400 characters of the output, and MLX peak memory.

## Hypotheses

| | Claim | Rule |
|---|---|---|
| **H1** | MLX has no prefill cliff on the fixtures up to 40K. | X: every size's median ≤ 2 × X's 15k median (exp_011's cliff rule). |
| **H2** | MLX prefill is no slower than Ollama's on the same text. | X ÷ O median prefill ≤ 1.05 at 15k **and** at 35k. |
| **H3** | MLX generates faster at short context. | X ÷ O median generation t/s at 4k ≥ 1.10 (exp_011 saw about 1.24). |
| **H4** | Today's MLX stack reproduces exp_011 on exp_011's own input. | F's median prefill within ±10 % of exp_011's repeat-1 values: 1.650 ms/tok at 15k, 2.161 at 35k. |
| **H5** | The repeated sentence did not change MLX's prefill speed. | F against X interpolated linearly to F's prompt length, within ±10 % at the 15k and 35k settings. |
| **H6** | H2 holds on natural text. | XN ÷ ON median prefill ≤ 1.05 at 15k **and** at 35k. |

**Validity check (not a hypothesis).** O_drift's 15k median must be within ±5 % of O's. If it is not, every Ollama-against-MLX comparison is reported with that drift beside it.

**Descriptive only.**
- X ÷ O and XN ÷ ON at every size, for both prefill and generation.
- Ollama's own cliff check, by H1's rule.
- MLX peak memory.
- Whether outputs stop early.

## What the results change

| Result | What follows |
|---|---|
| H1, H2 and H6 pass | MLX is at least as fast as the production runtime on real text, and moving the CasaSol answering model to an MLX server becomes a candidate (a separate, registered test with quality checks). |
| H2 or H6 fails | That move is off for speed reasons. |
| H5 fails | exp_011's numbers describe the repeated sentence, not text. Its post and log entry get a further dated note with these numbers. |
| H1 fails | exp_011's "no cliff on MLX" is withdrawn. |

## Known differences between the arms (stated, not controlled)

- **Weights.** MLX OptiQ is 5.0 bits per weight, mixed precision; the GGUF is Q4_K_M. The two arms are different quantisations of the same model, as in exp_011.
- **Tokenizers.** Each runtime tokenizes its own way. Comparisons are per token, and prompt lengths are reported.
- **Timing boundary.** MLX prefill time runs to the first generated token; Ollama's `prompt_eval_duration` stops at the end of prompt processing. That puts at most one token's sampling on MLX's side.
- **Generation length.** A one-sentence summary often ends before 128 tokens, so generation speed is measured over short outputs. Generated-token counts are reported.
